# 07 · UI: making the tools usable in the browser

## Goal

Every backend that ships in this initiative gets a page the user can open and act on, with
one shared look, one URL-state convention, and one set of table, chart and status components.
The earlier plan files each carried a thin "page" task; this file replaces those sections
with full specs and adds the shared kit they all depend on. When a plan file and this file
disagree about a page, this file wins.

State on 2026-09-09: T43 (breakouts) and T45 (trend) are live on the backend with nothing in
front of them. T47 put 28 symbols in the TopBar switcher. Nothing under `/scan`, `/regime`,
`/rotation` or `/flows` exists yet.

## Information architecture

```
TopBar    [dashboard controls on / , /report, /history]   [scan toolbar on the scan family]
NavBar    Dashboard · Report · History · Scan · Regime · Rotation · Flows · Settings
```

- **Scan family** = `/scan`, `/regime`, `/rotation`, `/flows`, `/overview`. They are universe
  pages, not symbol pages, so the TopBar's symbol switcher, expiry filter and snapshot
  selector do not apply. On those routes the TopBar renders a scan toolbar instead: bars
  freshness ("Bars through Mon 8 Sep · 47 symbols", from the `bars` block of
  `/api/health/capture`), the extended-capture freshness where relevant, and the theme toggle.
  The TopBar is therefore route-aware; nothing else about it changes.
- **Symbol pages** stay as they are. Any symbol shown on a scan page that has an option chain
  (`CORE_UNDERLYINGS ∪ EXTENDED_UNDERLYINGS`) is a link to `/?symbol=XLK` carrying the
  current filter; any other symbol is plain text with a tooltip "no option chain tracked".
- **URL drives every view.** `state/urlState.ts` gains `useScanParams()` next to
  `useDashboardParams()`: `view`, `n`, `k`, `lookback`, `sort`, `dir`, `group`, `benchmark`,
  `weeks`, `window`, each validated against an allowed list and defaulting the same way
  `filter` does. Deep links are the acceptance test for every page.

## Pages

### `/scan` — Breakouts and Trend (T44, absorbs the old T46)

Toolbar row under the TopBar: view toggle `Breakouts | Trend`; for Breakouts, `N` (20, 55),
`k` (3, 5, 10), `lookback` (40, 126, 252). All in URL state.

**Breakouts view.** Layout: left two thirds the summary table, right third the open-breakouts
panel; on narrow screens the panel drops below the table.

Summary table columns, from `GET /api/scan/breakouts`:

| Column | Source | Format |
|---|---|---|
| Symbol | `symbol` | `SymbolCell` |
| Events | `events` | count |
| Cont. / Fail / Pend. | `continued`, `failed`, `pending` | `8 / 3 / 1` |
| Rate | `rate` | `PercentileBar`; when `null`, the text `n<5` with the count in the tooltip. **This is the case at `lookback=40` today for 46 of 47 symbols, so it is the common case, not an edge case.** |
| Follow-through | `mean_follow_through_atr` | `formatAtr`, signed |
| Last event | `last_event.date`, `direction` | `13 Aug ↑` |
| Status | `status` | `StatusChip` |

Default sort: rate descending with `null` rates last; the direction toggles on header click.
Row click opens the detail panel for that symbol (see below).

Open-breakouts panel, from `open_breakouts`: symbol, direction, level, bars elapsed of `k`,
current excursion in ATR (`excursion_atr`), sorted by bars elapsed ascending so the freshest
breakout is on top. Empty → `EmptyState` saying no range breaks are inside their window.

`excluded` non-empty → a collapsed line "N symbols excluded for gaps" that expands to the
list with each `reason`.

Detail panel (drawer or right column, one component `BreakoutDetail`): a lightweight-charts
candlestick of the last `lookback` bars from `GET /api/bars/{symbol}?start=` with a marker
per event (`▲` below an up-break bar, `▼` above a down-break bar, colour by outcome) and a
horizontal line at the last event's level; below it the event table from
`GET /api/scan/breakouts/{symbol}`: date, direction, level, close, outcome, follow-through,
MFE, MAE. Symbols containing `^` must be percent-encoded in the request path; test `^VIX`.

**Trend view.** Same table component, from `GET /api/scan/trend`:

| Column | Source | Format |
|---|---|---|
| Symbol | `symbol` | `SymbolCell` |
| Composite | `composite` | `PercentileBar`, default sort desc |
| ADX14 | `adx14` | one decimal, tooltip shows `adx_pct` |
| ER20 | `er20` | two decimals, tooltip `er_pct` |
| CHOP14 | `chop14` | one decimal, tooltip `chop_pct` |
| VR z | `vr_z` | signed two decimals, tooltip `vr` |
| RV20 | `rv20` | `formatIv` |
| IV30 | `iv30` | `formatIv`; `null` → dash with tooltip "no option chain" |
| IV/RV | `iv_rv_ratio` | `formatRatio` |

A one-line legend above the table states the rule: composite is the mean of four
cross-sectional percentile ranks; IV/RV is shown but not part of it. Row click opens
`TrendDetail`: four `Sparkline`s over the `history` array from `GET /api/scan/trend/{symbol}`
(ADX, ER, CHOP, RV20), and the `current` block as a small key–value list.

Acceptance: renders against the fixtures including every `null` variant; `/scan?view=trend`
and `/scan?n=55&k=10&lookback=252&sort=rate&dir=asc` deep-link correctly and survive a nav
round trip to `/` and back; keyboard: header cells are buttons, rows are focusable and Enter
opens the detail; `npm test`, `npm run lint`, `tsc -b` pass; the supervisor opens the page
against the live backend and confirms HYG appears at the bottom of the rate sort with the
same numbers the API returns.

### `/rotation` — Sector rotation (T51, needs T50)

Toolbar: `group` (sectors, industries, assets), `benchmark` (SPY, RSP), `weeks` (6, 10, 14).

Layout: RRG chart left (square, min 480px), rank table and breadth block right; stacked on
narrow screens.

`RrgChart` (ECharts): scatter of the latest point per symbol with a `lines` series for each
trail, `markArea` quadrants shaded from the palette at low alpha, axes crossing at (100, 100),
axis labels "RS-ratio (approx.)" and "RS-momentum (approx.)", symbol labels always on, legend
toggles symbols. Hover shows symbol, both values, 4-week relative return. Quadrant names in
the corners: Leading, Weakening, Lagging, Improving.

`RankTable`: symbol, relative return 1w, 4w, 13w (signed pct), current quadrant chip; sorts
by any window. `Breadth`: RSP/SPY ratio with 20-day change, count of sectors above 20-day
and 50-day averages as `7 / 11`, and the label "sector-level breadth" with the tooltip
explaining why constituent breadth is not shown.

An info popover beside the chart title carries the approximation formula from plan 04.

Acceptance: fixture with a symbol pinned at (100, 100) renders it on the crosshair; trails
render in the right order (oldest faint, newest solid); `/rotation?group=industries&benchmark=RSP&weeks=6`
deep-links; suites and linters pass; live check.

### `/flows` — ETF flows (T53, needs T52)

Toolbar: `window` (5, 20, 60). Banner: data source per family and its last successful
update, from the `flows` health block; families with no source listed as unsupported.

`FlowBars` (ECharts horizontal bars): net flow as percent of AUM, sorted, diverging palette
around zero, value labels at bar ends. Funds with no data appear in a separate "no flow data"
list under the chart, never as a zero bar. A "history since <date>" note replaces the number
when the window exceeds the available history. Per-fund `Sparkline` of 60-day cumulative
flow in a compact table beneath.

Acceptance: fixture with one unsupported family and one fund with short history renders
both cases; `/flows?window=60` deep-links; suites and linters pass; live check on at least
one family.

### `RegimeStrip` (part of T54; visual spec lives here)

A single row of tiles, each: label, value, one-year percentile as a thin `PercentileBar`,
and a `StatusChip` for the rule label (`contango`, `backwardation`, `mixed`, or a percentile
band). Tiles with no data show `n/a` and the reason in the tooltip. Rendered at the top of
`/regime` and `/scan`. Tooltips carry the rule text from plan 06 verbatim.

### `/overview` — Continuation overview (T56, last)

One page that answers the question the initiative started with, in three blocks, all read
from the endpoints above with no new backend work:

1. **Tape**: the `RegimeStrip`.
2. **Where continuation is**: top 8 by breakout rate at the default `lookback`, with status,
   and top 8 by trend composite, side by side; below them the 8 worst by rate ("fading").
3. **Open now**: the open-breakouts panel from `/scan`, and the regime rows whose verdict is
   `continuation`.

Every block header links to its full page. This page becomes the nav's default landing when
the user says so; until then it is the last nav tab.

Acceptance: renders from the same fixtures as the source pages; every link carries URL state;
suites and linters pass.

## Likely first-contact failures

- The TopBar's 28-button switcher already wraps on narrow widths; adding a scan toolbar to
  the same component is the moment to give the switcher a `max-height` with overflow rather
  than letting the header grow.
- `^VIX` in a route path: React Router and `fetch` both need the caret encoded; a bare `^`
  works in some browsers and not in tests.
- ECharts `markArea` in dark theme with the default alpha turns the quadrants opaque; set
  the alpha explicitly from the palette.
- Sorting with `null` values: JavaScript's default comparator puts them arbitrarily; the
  `ScanTable` sort must pin `null` to the end for both directions.
- lightweight-charts markers need `time` as `yyyy-mm-dd` strings matching the bar series
  exactly; a marker on a date with no bar is silently dropped.

## Out of scope

Regenerating `api/types.ts` from OpenAPI (still hand-written by project convention), mobile
layouts beyond the stacking rules above, alerts or notifications, any persistence of table
preferences outside the URL.
